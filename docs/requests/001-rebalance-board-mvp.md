## 1. 배경과 목적

개인 투자자산을 **직접 만든 그룹별 목표 비중**에 맞춰 관리하는 1인용 웹 도구다.
매달 적립금으로 무엇을 몇 주 살지, 1월 정기 리밸런싱 때 무엇을 얼마나 사고팔지를 계산해 준다.

- 사용자는 1명(본인)이다. 로그인·회원 기능은 만들지 않는다.
- **3개월간 실제로 써 보는 것**이 이번 단계의 목적이다. 그래서 "매달 여는 데 걸리는 수고"를 줄이는 기능을 우선한다.
- 주문은 내지 않는다. 계산과 기록만 한다.

### 시안과의 관계

`reference/rebalance-board.html`은 화면과 계산 로직이 모두 동작하는 시안이다.
**화면 구성, 문구, 계산 함수는 시안을 그대로 옮긴다.** 새로 설계하지 않는다.
바꾸는 것은 아래 세 가지뿐이다.

| 항목 | 시안 | 이번 구현 |
|---|---|---|
| 저장 | 호스팅 서비스 전용 저장소(`window.claude.use('db')`) | 맥미니의 SQLite + REST API |
| 가격 | 사람이 넣어 준 값 | 매일 아침 자동 수집 |
| 보유 수량 갱신 | 손으로 수정 | "체결 반영" 버튼으로 자동 갱신 |

## 2. 운영 환경

- 실행 위치: 본인 소유 맥미니(상시 가동, macOS)
- 프로세스 관리: launchd
- 외부 접속: Cloudflare Tunnel. **반드시 Cloudflare Access(본인 이메일 인증)를 앞에 둔다.** 앱 자체에는 인증이 없으므로 Access 없이 터널을 열면 안 된다.
- 서버는 `127.0.0.1`에만 바인딩한다.
- 사용 기기: 아이폰(주 사용)과 PC 브라우저. 폰 폭 400px에서 가로 스크롤이 없어야 한다.

## 3. 기술 선택

| 영역 | 선택 | 이유 |
|---|---|---|
| 서버 | Python 3.12 + FastAPI + uvicorn | 가격 수집 라이브러리가 Python에 모여 있다 |
| 저장 | SQLite(파일 1개) | 1인용, 백업이 파일 복사로 끝난다 |
| 화면 | 빌드 없는 정적 파일(HTML + CSS + JS 모듈) | 시안을 거의 그대로 쓴다. React·번들러를 쓰지 않는다 |
| 스케줄 | launchd(매일 07:30 KST) | 맥미니 기본 기능 |
| 테스트 | pytest(서버), node --test(계산 모듈) | 설치 부담이 적다 |
| 패키지 관리 | uv | 가상환경과 실행을 한 번에 처리 |

현재 계획에는 API 키가 필요한 출처가 없다. 나중에 키가 생기면 `.env`에 두고 저장소에 올리지 않는다.

## 4. 데이터 구조

### 4.1 포트폴리오 문서

시안의 구조를 그대로 쓴다. 서버는 이 문서를 JSON 통째로 저장하고 버전 번호를 붙인다.

```jsonc
{
  "monthly": 3080000,        // 월 적립금(원)
  "carry": 0,                // 이월 현금(원)
  "band": 5,                 // 허용 밴드(±%p)
  "groups": [
    { "id": "nq", "name": "나스닥100", "target": 69.3,
      "mode": "lead",        // "lead" = 대표 종목만 사기, "ratio" = 비율대로 나눠 사기
      "lead": "133690",      // 매수할 종목 코드(lead 모드)
      "sell": "133690" }     // 먼저 매도할 종목 코드(lead 모드)
  ],
  "assets": [
    { "name": "TIGER 미국나스닥100", "ticker": "133690",
      "market": "KR",        // KR | US | GOLD | CRYPTO | CASH
      "qty": 461, "avg": 146172,   // 평균단가는 해당 통화 기준(US는 달러)
      "unit": 1,             // 매매 단위: 1 | 0.01 | 0.0001
      "account": "ISA",      // 일반 | ISA | 연금저축 | IRP | 업비트 | 기타
      "group": "nq",         // 소속 그룹 id. 없으면 미분류
      "inner": 1,            // 그룹 내 비율(ratio 모드에서만 사용)
      "exclude": false,      // true면 리밸런싱에서 제외(전세보증금 등)
      "manual": false }      // true면 종목코드·시장을 직접 입력한 종목
  ]
}
```

### 4.3 SQLite 테이블

| 테이블 | 용도 | 주요 컬럼 |
|---|---|---|
| `portfolio` | 포트폴리오 문서 1행 | `id=1`, `doc`(JSON), `version`, `updated_at` |
| `quotes` | 종목별 일별 종가 | `ticker`, `date`, `close`, `currency`, `source`, PK(`ticker`,`date`) |
| `fx` | 일별 환율 | `date`, `usdkrw`, `source` |
| `trades` | 체결 기록 | `id`, `date`, `ticker`, `side`, `qty`, `price`, `currency`, `fx`, `kind`(monthly/annual/manual) |

`usage_log`는 3개월 뒤 "실제로 매달 썼는가"를 확인하는 용도다. 화면에는 노출하지 않는다.

## 6. 계산 규칙

`reference/rebalance-board.html`의 다음 함수를 **로직 변경 없이** `web/js/rebalance.js`로 옮긴다.
DOM에 접근하지 않는 순수 함수로 만들고, 화면 코드는 그 결과만 그린다.

| 시안 함수 | 역할 |
|---|---|
| `buildUnits` | 그룹과 종목을 "리밸런싱 단위"로 변환 |
| `allocateContribution` | 예산을 단위별 부족분에 배분 |
| `planMonthly` | 매매 단위로 내림한 뒤 남은 돈으로 추가 매수 |
| `maxDrift` | 목표 대비 최대 이탈(%p) |
| 1월 리밸런싱 블록(`renderBoard` 안의 `annual` 부분) | 단위별 매수·매도 수량 |

규칙을 말로 풀면 다음과 같다.

**평가액**
- 종목 평가액 = 수량 × 현재가. US 종목은 환율을 곱한다.
- 종가가 없는 종목은 평균단가로 대신 계산하고 화면에 경고를 띄운다.
- `exclude`인 자산은 모든 비중 계산에서 뺀다. 총액 옆에 "제외 자산 포함 금액"만 따로 보여 준다.

**리밸런싱 단위**
- `ratio` 그룹: 종목 하나가 1단위. 단위 목표 = 그룹 목표 × (종목 inner ÷ 그룹 inner 합계).
- `lead` 그룹(종목 2개 이상): 그룹 전체가 1단위. 평가액은 합산하고, 매수는 `lead` 종목으로만 한다.
- 종목이 1개인 그룹은 mode와 무관하게 그 종목이 1단위다.
- 미분류 종목: 목표 0%인 1단위. 화면에 "그룹을 지정하라"는 경고를 띄운다.
- 그룹 목표 합계가 100이 아니면 합계로 나눠 비율로 환산하고 경고를 띄운다. 종목이 없는 그룹은 합계에서 뺀다.

**이번 달 적립 배분(정액식)**
1. 예산 = 월 적립금 + 이월 현금.
2. 적립 후 총액 기준으로 단위별 부족분(목표 금액 − 현재 평가액, 음수는 0)을 구한다.
3. 부족분 합계가 예산보다 크면 부족분 비율대로 나눈다. 작으면 부족분을 모두 채우고 나머지를 목표 비중대로 나눈다.
4. 배정액을 매매 단위로 내림해 수량을 정한다.
5. 남은 돈으로, 아직 목표에 가장 못 미치는 단위부터 1매매단위씩 더 산다. 살 수 있는 단위가 없으면 멈춘다.
6. 배정은 됐지만 1단위 가격에 못 미쳐 0주가 된 종목은 "이번 달 보류"로 표시한다.
7. 매도는 하지 않는다.

**1월 정기 리밸런싱**
- 기준 총액 = 현재 총액 + 예산.
- 단위별 차이 = 목표 금액 − 현재 평가액.
- 차이가 양수면 매수 종목을 매매 단위로 내림해 산다.
- 차이가 음수면 `sell` 종목부터 팔고, 모자라면 같은 그룹의 다른 종목을 순서대로 판다. 보유 수량을 넘겨 팔지 않는다.
- 미국 상장 자산 매도분의 양도차익(매도 수량 × (현재가 − 평균단가) × 환율)을 합산해 안내 문구에 보여 준다.

**상태 판정**
- 최대 이탈 ≤ 밴드의 절반: 양호
- 최대 이탈 ≤ 밴드: 주의
- 그 이상: 리밸런싱 필요

## 7. 화면

탭 3개. 주소 해시(`#board`, `#portfolio`, `#holdings`)로 이동한다. 세부 모양은 `docs/DESIGN.md`를 따른다.

### 7.1 대시보드
1. 경고 영역(가격 누락, 환율 누락, 미분류 종목)
2. 요약 4칸: 총 평가액(평가손익, 제외 자산 포함 금액) · 최대 이탈 · 상태 · 적립만으로 해소
3. 그룹 비중 막대
4. 종목별 비중 막대(`lead` 그룹 소속 종목은 목표선 없이 "그룹명 합산"으로 표시)
5. 보유 현황 표(현재가, 평균단가, 평가액, 평가손익, 수익률)
6. 이번 달 적립 배분 표 + 안내 문구 + **[체결 반영] 버튼**
7. 1월 정기 리밸런싱 표 + 안내 문구 + **[체결 반영] 버튼**

### 7.2 포트폴리오
- 적립 방식: 정액식만 동작. 정량식 버튼은 "준비 중"으로 비활성.
- 월 적립금, 이월 현금, 허용 밴드
- 그룹 카드 목록: 이름, 현재 비중, 목표 %, 삭제, 규칙(종목 2개 이상일 때만), 소속 종목 행(그룹 이동 선택, 현재 비중, 그룹 내 비율)
- 미분류 종목 카드, 리밸런싱 제외 자산 안내
- [그룹 추가] 버튼, 목표 합계 게이지

### 7.3 보유 자산
- 종목 검색(국내상장 / 해외상장 / 금 / 코인 필터). 결과를 누르면 종목이 추가되고 수량 칸으로 이동
- "직접 입력"으로 목록에 없는 종목 추가
- 종목 카드: 자산명, 종목코드(읽기 전용), 자산군, 계좌, 매매 단위, 보유 수량, 평균단가, 현재가(읽기 전용), 평가액과 손익, 리밸런싱 제외 체크, 삭제

### 7.4 종목 검색 규칙
`data/symbols.json`의 각 행은 `[코드, 이름, 상장구분, 시가총액(억원), 별칭, 보조순위, 자산군]`이다.

- 정렬 1순위는 유사도 단계: 코드 일치(100) > 이름 일치(95) > 별칭 일치(90) > 이름이 검색어로 시작(80) > 코드가 검색어로 시작(75) > 별칭에 포함(60) > 이름에 포함(50).
- 2순위는 시가총액, 3순위는 보조순위(ETF 거래대금·인기순), 4순위는 이름순.
- 비교할 때 공백, `-`, `_`, `.`, 괄호, `&`를 지우고 소문자로 맞춘다.
- 상위 30개만 보여 준다. 별칭은 `|`로 구분돼 있다.

## 8. 시안에서 고쳐야 할 점

구현하면서 함께 바로잡는다.

1. **달러 현금**: 외화RP처럼 달러로 보유한 현금은 지금 원화 환산액을 손으로 넣는다. 현금 자산에 통화(KRW/USD) 선택을 추가하고, USD면 환율을 자동 적용한다.
2. **현금 수량 표기**: 현금 자산의 매수안이 "입금 185,043"으로 나온다. "입금 185,043원"으로 단위를 붙인다.
3. **가격 기준 표기**: 종목마다 종가 날짜가 다를 수 있다(미국은 하루 늦다). 상단에는 수집 시각을, 종목 카드에는 종목별 종가 날짜를 보여 준다.
4. **동시 수정 충돌**: 폰과 PC에서 동시에 열면 나중 저장이 앞의 것을 덮는다. PUT이 409를 받으면 최신 문서를 다시 불러오고 "다른 기기에서 수정돼 새로 불러왔습니다"를 띄운다.

## 9. 가격 수집

매일 07:30 KST에 `server/jobs/fetch_prices.py`를 실행한다. 포트폴리오에 있는 종목만 수집한다.

| 시장 | 1순위 출처 | 비고 |
|---|---|---|
| KR(주식·ETF) | yfinance (`005930.KS`, 코스닥은 `.KQ`) | API 키 불필요. 조회되지 않는 종목은 FinanceDataReader로 다시 시도한다 |
| US(주식·ETF) | yfinance | 비공식 라이브러리. `BRK.B` 같은 코드는 `BRK-B`로 바꿔 조회 |
| 환율 | yfinance `KRW=X` | 수집 시점 값 |
| CRYPTO | 업비트 공개 시세 `GET https://api.upbit.com/v1/ticker?markets=KRW-BTC` | 키 불필요. 전일 종가는 `prev_closing_price`(업비트 일봉은 KST 09:00 기준) |
| GOLD(KRX 금현물) | **조사 필요** | 아래 참고 |
| CASH | 수집하지 않음 | 가격 1 |

**구현 전에 조사해서 보고할 것**
- KRX 금현물(1g 종가)을 받을 수 있는 출처. 후보는 공공데이터포털의 금융위원회 일반상품 시세 API다. 안 되면 금 가격은 화면에서 직접 입력하게 한다.
- 보유 종목 전체가 yfinance에서 조회되는지. 국내 종목은 코스피 `.KS`, 코스닥 `.KQ` 접미사를 붙이며, 어느 쪽인지는 `data/symbols.json`만으로 알 수 없으므로 `.KS`를 먼저 시도하고 없으면 `.KQ`를 시도한다. 영문이 섞인 신형 ETF 코드처럼 조회되지 않는 종목은 FinanceDataReader로 받는다.

증권사 API(한국투자증권 등)는 쓰지 않는다. 전일 종가만 필요하므로 키 발급·토큰 관리가 필요한 출처는 과하다.

**수집 규칙**
- 출처마다 `server/prices/<market>.py`에 `fetch(tickers) -> {ticker: (date, close)}` 함수 하나로 통일한다.
- 한 종목이 실패해도 나머지는 저장한다. 실패 종목은 직전 종가를 유지하고 화면에 종가 날짜가 오래됐음을 보여 준다.
- 종가가 3영업일 넘게 갱신되지 않은 종목은 대시보드 경고에 넣는다.
- 주말·공휴일에는 새 값이 없어도 오류로 보지 않는다.

## 10. 체결 반영 (3개월 사용의 핵심 기능)

매달 수량과 평균단가를 손으로 고치면 금방 안 쓰게 된다. 매수안을 한 번에 반영하는 기능을 넣는다.

1. "이번 달 적립 배분" 아래 [체결 반영]을 누르면 확인 패널이 열린다.
2. 패널에는 매수안의 종목, 수량, 가격이 미리 채워져 있다. 실제 체결가와 수량으로 고칠 수 있고, 행을 뺄 수도 있다.
3. [반영]을 누르면 종목마다 다음과 같이 갱신한다.
   - 새 수량 = 기존 수량 + 체결 수량
   - 새 평균단가 = (기존 수량 × 기존 평균단가 + 체결 수량 × 체결가) ÷ 새 수량
   - 매도는 수량만 줄이고 평균단가는 유지한다.
   - 이월 현금 = 예산 − 실제 사용 금액(매도 대금은 더한다)
4. 체결 내역을 `trades`에 기록한다.
5. 반영 직후 화면에 "되돌리기"를 30초간 보여 준다. 누르면 직전 포트폴리오 문서로 복구하고 해당 `trades` 행을 지운다.

브라우저의 `confirm()` 대신 화면 안에 확인 패널을 만든다.

## 14. 주의할 점

- 화면의 세금 문구(해외주식 양도세 250만 원 공제, 22%)는 안내용이다. 계산에 반영하지 않는다.
- 금액은 화면에 원 단위로 반올림해 보여 주되, 내부 계산은 반올림하지 않은 값으로 한다.
- 개인 금융 데이터다. 외부 분석 도구, 오류 수집 서비스, CDN 스크립트를 붙이지 않는다. 글꼴(Google Fonts)만 예외다.
- 모르는 API 사양은 추측하지 말고 문서를 확인한 뒤 보고한다.
